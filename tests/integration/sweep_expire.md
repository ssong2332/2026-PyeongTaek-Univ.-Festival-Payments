# T-18 만료 스윕 검증

`sweep_expire.sql`은 **독립 `festival_sweep_test` DB 전용**이다.
`.github/workflows/sweep-expire.yml`이 PostgreSQL 17에서 실행한다.
운영 DB나 공유 Supabase 프로젝트에서 실행하지 않는다.

대상 선정·오류 처리 테스트는 트랜잭션 안에서 `transition_order`를 호출 기록용
대역으로 바꾸고 마지막에 롤백한다. 실제 함수의 재고 복구·이력은 별도 테스트로 검증한다.
운영 마이그레이션에는 대역을 넣지 않는다.

검증 범위: 9분59초/10분 경계, 현금·계좌이체 공통 처리, 송금 신고 60분 제외,
paid·cooking·터미널 제외, 기본 설정과 변경 반영, 중복 호출, CAS 충돌 건너뛰기,
다른 오류 전파·롤백, 잘못된 설정 거부, 실행 권한과 SECURITY INVOKER.

`sweep_expire_transition.sql`은 대역 없이 실제 함수의 재고 복구·system 이력·
중복 실행을 확인한다. CI는 0007·0008·0009를 필수로 적용한 뒤 두 테스트를 모두 실행한다.

운영 적용 순서는 Architecture 번호 배정에 따라 0008 → 0009 → 0011이다.
0011은 T-18 만료만 구현하므로 `completed`는 0이며, T-19가 0012에서 확장한다.
pg_cron(0015)과 서비스 호출은 후속 작업이다.

## 후속 연결 검증

- 실제 Supabase 환경에서 두 세션의 스윕 동시 실행 및 관리자 입금 확인·송금 신고와의 경쟁 검증.
  스윕은 대상 행을 `FOR UPDATE SKIP LOCKED`로 잠그므로 다른 트랜잭션이
  잠근 행은 다음 스윕에서 다시 평가한다.
- T-17·T-32 및 BE1의 호출 경로까지 연결해 선행 상태 변경이 보존되는지 확인.

## 2026-09-25 로컬 검증 기록

Docker/PostgreSQL 실행 파일이 없는 환경에서 임시 PGlite 메모리 DB로 검증했다.
저장소 의존성 및 운영 DB는 변경하지 않았다. PGlite의 DB 이름은 `postgres`여서
테스트 입력의 DB 이름 가드만 메모리 DB 이름으로 치환했다.

- 현재 dev의 0001 + 0011: 스윕 계약 테스트 통과.
- DB1 브랜치 `89570b5`의 0007·0008 및 BE1 브랜치 `d432d38`의 0009와
  0011: 계약 테스트 및 실제 함수의 재고 복구·이력·중복 실행 테스트 통과.
- 해당 기록 시점에는 실제 Supabase, 다중 세션 동시성, GitHub CI가 미검증이었다.
  위 브랜치 SQL은 검증에만 사용했으며 이 작업에 복사하거나 병합하지 않았다.
