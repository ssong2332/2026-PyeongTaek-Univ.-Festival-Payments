# tests/integration — 로컬 Supabase 실물 대상(mock 없음, 파일 직렬). `npm run test:integration`은 T-02에서 등록. Docker 없는 PC는 CI 잡 ②(T-02)에 맡긴다.

## T-36 시드 검증

`seed.sql`은 Vitest가 아닌 CI의 별도 `psql` 단계에서 실행한다. CI 로컬
Supabase 안에 `festival_seed_test` DB를 생성하고 실제 마이그레이션을 적용한 뒤
실제 `supabase/seed.sql`을 두 번 실행한다. 운영 DB에는 실행하지 않는다.
이름이 다른 DB에서 실행하면 즉시 실패하며, CI 종료 시 Supabase와 함께 정리된다.

- 메뉴 4개와 확정 가격, 설정 8개와 기본값, 픽업 번호 시작값 0
- 재실행 후 메뉴·번역·설정·카운터 중복 없음
- 모든 메뉴의 한국어·영어 이름 존재 및 빈 문자열 없음
- 변경된 재고·수동 품절·활성 상태 보존
- 변경된 운영 설정·송금 설정·픽업 카운터 보존

자동 시드 설정은 비활성 상태를 유지한다. 이 검사는 시드 파일을 명시적으로
실행하므로 해당 설정과 무관하다. 초기 재고 0과 옵션 미정은 별도 확정이 필요하다.
