# tests/integration — 로컬 Supabase 실물 대상(mock 없음, 파일 직렬). `npm run test:integration`은 T-02에서 등록. Docker 없는 PC는 CI 잡 ②(T-02)에 맡긴다.

## T-36 시드 검증

`seed.sql`은 Vitest가 아닌 CI의 별도 `psql` 단계에서 실행한다. CI 로컬
Supabase 안에 `festival_seed_test` DB를 생성하고 실제 마이그레이션을 적용한 뒤
실제 `supabase/seed.sql`을 반복 실행하고 구 메뉴가 있던 DB로의 전환도 검증한다. 운영 DB에는 실행하지 않는다.
이름이 다른 DB에서 실행하면 즉시 실패하며, CI 종료 시 Supabase와 함께 정리된다.

- 확정 메뉴 10개와 가격·초기 재고 100개, 옵션 그룹 30개·옵션 90개(모든 추가 가격 500원)
- 재실행 후 메뉴·옵션·번역·설정·카운터 중복 없음
- 모든 메뉴와 옵션의 한국어·영어 번역 존재 및 빈 문자열 없음
- 변경된 재고·수동 품절·활성 상태와 옵션 활성 상태 보존
- 변경된 운영 설정·송금 설정·픽업 카운터 보존
- 기존 4종 시드의 불닭 치즈·맛다시 메뉴는 ID·재고·주문 참조를 보존한 채 1회 판매 종료

자동 시드 설정은 비활성 상태를 유지한다. 이 검사는 시드 파일을 명시적으로
실행하므로 해당 설정과 무관하다. 확정 메뉴를 운영에 적용하는 작업은 DB1 담당이다.

## 선행 작업과의 경계

설정 키는 최신 dev의 ADR-0004(2026-09-24) 기준 6개이며, T-33 계좌 안내
API가 사용하는 `transfer.bank_name`, `transfer.account_number`,
`transfer.account_holder`를 유지한다. 메뉴 ID·가격·재고 보존 및
`pickup_number` 계약은 변경하지 않는다. 기존 기본·뿌링클 메뉴 ID를 유지하고,
성격이 달라진 메뉴에는 새 ID를 부여해 과거 주문 집계를 보존한다.

시드는 폐기된 간편결제 키를 새로 만들지 않으며 기존 행을 삭제하지 않는다.
기존 DB의 간편결제 키 삭제와 주문 컬럼·enum 변경은 DB1의 T-53 마이그레이션
책임이다. T-53 전후 어느 시점에 시드를 재실행해도 폐기 키를 다시 만들지 않는다.
T-53 적용 전 기존 DB에는 과거 키가 남아 있을 수 있으므로 설정 총 개수 6개
검사는 초기화된 독립 테스트 DB 기준이다. T-53 병합 후 전체 마이그레이션을
적용한 통합 검증은 별도로 필요하다. 현재 테스트 통과를 T-03·T-53 완료로
간주하지 않는다.
