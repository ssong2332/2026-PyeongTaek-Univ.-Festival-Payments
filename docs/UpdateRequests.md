# 문서 갱신 요청 — {{PROJECT_NAME}}

> 소유자: docs (행 추가 전담, append-only). docs는 README·CHANGELOG 외 문서(PRD·Architecture·DECISIONS·adr·Tasks)를 직접 고치지 않는다 — 실제 상태와 어긋난 것을 발견하면 여기 행을 남겨 소유 에이전트가 세션이 바뀌어도 처리하게 한다.

## 요청 목록

| # | 날짜 | 대상 문서 | 절 | 낡은 내용 | 코드가 실제로 보여주는 것 | 담당 에이전트 | 상태 |
|---|---|---|---|---|---|---|---|

행이 비어 있으면 지금까지 보고된 드리프트가 없다는 뜻이다 — docs가 실제로 문서-코드 불일치를 발견하면 그때 첫 행을 추가한다. 예시 행을 미리 채워두지 않는다: 상태 칸에 `open`이 리터럴로 있으면 planner·architect가 실제 열린 요청으로 오인할 수 있다 (2026-08-18, 테스트 프로젝트 실행 중 실측 — planner가 스스로 판별해 처리하지 않았지만, 다른 판단으로는 걸러지지 않을 수 있는 함정이었다).

## 규칙

- 행 추가는 docs만 한다. docs는 과거 행을 다시 쓰거나 지우지 않는다.
- 상태 열만 예외다: 행에 이름 오른 담당 에이전트(planner/architect)가 처리한 뒤 `open` → `resolved`로 바꿀 수 있다 — implementer가 docs/Tasks.md의 자기 작업 Status 열만 바꿀 수 있는 것과 같은 구조(AGENTS.md 문서 소유권).
- 그 외는 전부 읽기 전용이다.
- 같은 문서·같은 절에 이미 열린(`open`) 행이 있으면 중복 행을 만들지 않는다 — 처리를 기다리는 요청이 이미 있다는 뜻이다.
