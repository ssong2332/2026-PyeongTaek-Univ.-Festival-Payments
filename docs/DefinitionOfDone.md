# DefinitionOfDone — {{PROJECT_NAME}}

> 소유자: 사용자 | implementer가 검증 전환 요청 전에 자가 점검하고, QA가 최종 판정한다.
> 예외: "Tasks 검증중 상태" 항목은 implementer 자가 점검 대상이 아니다 (그 전환은 요청을 받은 planner가 수행 → QA가 확인).

## 완료 판정 체크리스트

- [ ] 요구사항 ID(F-xx)와 구현이 1:1로 대응된다 — 대응 안 되는 구현(범위 밖)이 없다.
- [ ] 빌드가 성공한다 (검증된 명령어 원문 사용, 출력 확보).
- [ ] 테스트가 전부 통과한다 (실행 출력 확보 — 출력 없이 통과 주장 금지).
- [ ] 새 기능의 새 테스트는 구현 전에 먼저 실패를 확인한 뒤 통과시킨 것이다 (Red-First — 통과만 확인한 테스트는 무엇을 검증하는지 증명하지 못한다. AGENTS.md 검증 루프, `.agents/skills/tdd-practitioner/SKILL.md` 참조).
- [ ] 버그 수정에는 수정 전 실패를 확인한 재현 테스트가 있다.
- [ ] 화면에서 확인 가능한 인수 기준(AC)은 그 화면을 실제로 띄워 확인한 증거(스크린샷, 수동 확인 로그 등)로 충족된다 — 테스트 러너 통과나 빌드 성공은 화면이 실제로 그렇게 보인다는 증거가 아니다 (해당 AC 없으면 "해당 없음". Claude Code에서는 implementer·QA가 Browser pane 도구(`mcp__Claude_Browser__*`)로 직접 확인한다 — 툴 목록은 각 에이전트 파일 참조. 그 도구가 없는 도구(Codex·안티그래비티 등)에서는 메인 세션이 직접 확인해 증거를 첨부한다 — 증거 없이 이 항목을 통과로 표시하지 않는다).
- [ ] CodingRules.md 위반이 없다.
- [ ] 에러 케이스(잘못된 입력, 빈 값, 경계값)를 처리했다.
- [ ] docs/Tasks.md에서 해당 작업이 "검증중" 상태이고 근거 열에 구현 근거가 기록돼 있다 ("완료" 전환은 QA 통과 후 planner가 한다 — 완료를 여기서 요구하면 순환).
- [ ] 커밋이 GitWorkflow.md 규칙(브랜치·메시지)을 따랐다 (이 작업의 커밋이 아직 없으면 "해당 없음 — 커밋 미생성"으로 판정).

### 조건부 항목 (해당 프로젝트만)

- [ ] 보안 대상(인증·결제·개인정보): `.agents/skills/security-audit/SKILL.md` 체크리스트 통과 — 시크릿 하드코딩 0건, 인가(IDOR) 서버측 검증, 민감 정보 로그 미노출, 신규 의존성 출처 확인.
- [ ] 웹 UI: `.agents/skills/web-performance/SKILL.md`의 접근성 필수 항목(alt·키보드 포커스·명도 대비·label) 통과.
- [ ] UI 있는 프로젝트: 이번 작업이 건드린 화면에 대해 docs/PRD.md "화면" 절이 정의한 상태(빈 값·로딩·에러 등)가 전부 구현돼 있다 — 정상 경로만 구현하고 나머지 상태를 나중으로 미룬 것은 미통과 (PRD가 "없음 — 사유"로 적은 상태는 해당 없음).
- [ ] 계층형 구조 채택: `.agents/skills/clean-architecture/SKILL.md`의 검증 체크리스트(프레임워크 객체 유입 없음, DB 코드 위치, 순환 참조 없음) 통과.

## 판정 규칙

| 상황 | 판정 |
|---|---|
| 체크 항목 전부 통과 | 완료 → 리뷰/검증 단계로 |
| 하나라도 미통과 | 미완료 → 구현 단계 계속 (통과 못 한 항목을 보고에 명시) |
| 항목이 이 프로젝트에 해당 없음 | 삭제하지 말고 "해당 없음 + 사유" 기재 (빈칸 금지 — 빈칸은 "불필요"와 "잊음"을 구별 못 한다) |
| 구현 보고서의 통과 주장을 재실행으로 확인 못 함 | 통과로 세지 말고 `미검증` 표시 — 기본은 이 항목 때문에 미완료 |
| 미검증 항목이 있고 나머지는 전부 통과 | QA가 "같은 세션에 원본 실행 출력이 첨부돼 있어 재현은 못 해도 위험이 낮다"고 판단하면, 근거 열에 `미검증 수용: {이유}`를 명시하고 완료로 진행할 수 있다 — 이유 없이 조용히 통과로 세는 것은 금지 (예: 재실행 불가 사유가 implementer 지시·환경 제약처럼 코드 결함이 아닌 경우) |
