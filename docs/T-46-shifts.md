# T-46 교대 스케줄 관리 검증

F-40 / Open Question #30: 이름 텍스트 등록, 날짜·시작·종료·역할, 자유 시간대, 겹침 허용, 교대 알림 없음. 선행 T-13의 관리자 라우트 보호·RLS 정책을 따른다.

## 구현

- `/admin/shifts`: 관리자 보호 레이아웃 안에 페이지를 두고 기존 관리자 화면에서 이동 링크 제공.
- `shifts`: `0100_shifts.sql`(2차 01xx 규칙). 이름 최대 80자·역할 최대 100자, 분 단위 시각, 종료 > 시작, 같은 날짜 안의 구간. 0분 구간과 자정 넘김은 저장 거부. 같은 시간대 복수 담당자는 허용.
- 서버 검증과 DB CHECK로 빈 이름/역할·시간 역전 방지. 모든 관리자 API는 인증을 먼저 확인하고 service_role 저장소를 사용한다.
- anon 읽기/쓰기 거부, authenticated 읽기만 허용. 직접 브라우저 쓰기는 거부.
- KST 날짜·시각 기준 [시작, 종료)로 현재 담당자 산출. 30초마다 현재 시각 갱신. 목록은 전체 날짜를 날짜·시작·이름 순으로 표시.
- 조회 실패를 빈 목록으로 표시하지 않고 재시도 제공. 최초 조회 실패 시 저장 잠금. 저장 실패는 입력 보존과 오류 안내, 처리 중 폼 잠금. 삭제는 확인 후 수행. 미존재 수정/삭제는 404.

## 검증

새 도메인 테스트를 구현 전에 작성해 미구현 실패를 확인한 뒤 통과시켰다.
단위 테스트: KST 날짜 경계·겹침·시작 포함/종료 제외·종료 역전/동일·잘못된 날짜/시간/추가 필드, CRUD API 응답·인증 우선·UUID·404/500 정보 비노출, 화면 CRUD·저장 잠금·실패 입력 보존·재시도·세션 만료.

로컬 브라우저에서 임시 메모리 저장소를 주입해 다음을 실제 화면으로 확인했다(2026-10-02). 검증용 라우트는 PR에 포함하지 않았다.
- 겹치는 담당자 2명과 전체 표 3행 표시.
- 이름·역할 입력 → 등록 결과 4행 → 수정 결과 역할 반영 → 삭제 확인 후 3행.
- 키보드로 종료 시각을 시작 이전으로 바꿨을 때 즉시 검증 메시지.
- 0건: 등록된 스케줄 없음 + 추가 버튼, 현재 담당자 없음.
- 조회 로딩: 입력·등록 잠금. 조회 실패: 오류 및 새로고침, 0건 상태로 오표시하지 않음.
- 저장 실패: 오류 안내와 입력 보존.
- 실제 보호 라우트 `/admin/shifts`의 비로그인 접근 → `/admin/login`.
UI 검증은 메모리 테스트 데이터로 수행했고, 실제 PostgreSQL 저장·수정·삭제·CHECK·RLS는 `tests/integration/t46-shifts.test.ts`를 GitHub CI 로컬 Supabase에서 실행한다.

## 운영 반영

팀장 리뷰·병합 이후 DB1이 적용한다. 마이그레이션 순서는 기존 예약 `0018`(T-51)·`0019`(pg_cron) 다음 `0100`(T-46)이다. 운영 DB는 이 구현·검증에서 변경하지 않았다. 운영 배포 전 마이그레이션 적용과 해당 화면/API 동작을 확인한다. Tasks·Notion 상태 변경은 하지 않았다.
