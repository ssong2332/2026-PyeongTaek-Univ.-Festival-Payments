# T-01 구현·검증 기록

검증일: 2026-09-22. 담당: BE1. 팀장에게 검증 전환을 요청하기 위한 기록이며 완료 판정은 아니다.

## 구현 범위

- Next.js 16.3.5, React 19.2.8, TypeScript, Tailwind CSS. `create-next-app` 공식 도구로 생성하고 `package-lock.json`으로 설치할 패키지 버전을 고정했다.
- 팀 문서의 Node 20 기준에 따라 `.nvmrc`는 20.20.2. 검증 시 시스템 Node 25 대신 별도 Node 20.20.2를 사용했다.
- Vitest: 순수 TS 기본 환경, `@/` 경로, `tests/unit/**/*.test.{ts,tsx}`만 실행. 컴포넌트 테스트용 Testing Library·jsdom 설치.
- Playwright: Android/iPhone Chromium 에뮬레이션과 데스크톱 Chromium, 파일 직렬 실행, 전용 개발 서버. 실제 iOS Safari 검증은 아님.
- ESLint: Next.js·TypeScript 규칙, 순환 참조, `domain`·`services`에서 프레임워크 코드 가져오기 제한, 고객 코드의 직접적인 서비스 키 참조 제한. 비밀값 간접 전달까지 검출하는 보안 분석기는 아님.
- CI: 모든 코드 업로드(push)와 `main` 병합 요청(PR)에서 `unit-build` 작업 실행(패키지 설치 → 코드 규칙 검사 → 단위 테스트 → 빌드). 읽기 전용 권한, 빌드용 임시 환경변수. 브라우저 검사(E2E)·통합 테스트의 자동 실행은 이번 범위 밖.

## 로컬 실행 결과

| 검사 | 결과 |
|---|---|
| 구현 전 실패 확인: 단위 검사 | `locales` 모듈 구현 전 해당 모듈을 가져오지 못해 실패함을 확인 |
| 수정 전 실패 확인: 브라우저 검사 | 문서 언어가 `en`일 때 기대값 `ko`와 달라 실패함을 확인 |
| npm run lint | 종료 코드 0 |
| npm run test | 테스트 파일 1개·검사 1개 통과 |
| npm run test:e2e | 안드로이드·아이폰·데스크톱 설정에서 3개 통과. 정상 응답(HTTP 200)과 한국어 설정(`lang=ko`) 확인 |
| npm run build | 빌드·TypeScript 검사 성공, 첫 화면(`/`)의 정적 페이지 생성 |
| 의존성 설치 감사 | npm 검사에서 알려진 취약점 0건 보고 |

초기 빌드는 실행 환경의 포트 사용 제한으로 실패했다. 실행 권한 허용 후 이전 실패 캐시를 제외하고 재실행하여 성공했다.
T-01은 동작 확인용 기본 페이지·상수만 추가한다. 주문 기능·고객 메뉴판은 후속 작업이다. 입력 처리 로직이 없으므로 정상/경계/예외 5개 업무 테스트와 주문 화면 인수 기준(AC)는 해당 없음.

## 팀 공유 순서 / 아직 필요한 근거

1. 변경 검토 후 `chore: T-01 프로젝트 기본 환경 및 테스트 도구 설정`이라는 메시지로 커밋한다.
2. `feat/T-01-harness` 브랜치를 GitHub에 업로드하고 `main`에 합치기 위한 검토 요청(PR)을 만든다.
3. GitHub Actions에서 `unit-build` 자동 검사가 통과한 결과 링크를 확보한다. 아직 실행하지 않았으며 내 컴퓨터에서의 성공만으로 자동 검사 성공을 판단하지 않는다.
4. 팀장에게 검토 요청(PR)·자동 검사 결과 링크·이 기록을 첨부해 검증 전환을 요청한다. `Tasks.md`의 상태·근거 표는 팀장이 갱신한다.
5. 저장소 관리자가 `main` 보호 규칙에서 검토 요청(PR)과 `unit-build` 검사 통과를 필수 조건으로 설정한다. 아직 설정 여부를 확인하지 않았다.
6. 팀장/리뷰어 확인과 병합 후 T-01 완료로 판정한다.

`npx supabase start`는 Docker 불가 결정으로 로컬 미검증이다. T-02에서 GitHub Actions 통합 테스트 환경과 명령을 검증한다.
