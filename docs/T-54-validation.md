# T-54 서비스 연결 검증 기록

## 범위

- #156에서 확정한 입금 확인 정책과 #164의 `0106_atomic_transition.sql`을 기준으로 #161 서비스 변경을 검토한다.
- 계좌이체 `confirm_payment`, 현금 `confirm_cash`, 기존 `paid` 주문의 `start_cooking`은 항상 `transition_order_if_cancel_unchanged`를 호출한다. 두 취소 시각이 NULL이어도 인자를 명시한다.
- 그 외 상태 전환은 기존 `transition_order`를 사용한다. 상태 머신의 사전 거부와 DB의 `STATE_CHANGED`(409) 매핑은 유지한다.

## 이 격리 브랜치에서 확인한 항목

| 항목 | 결과 |
|---|---|
| TypeScript `npm run typecheck` | 통과 |
| 서비스·저장소 관련 단위 테스트 | 2개 파일, 32개 통과 |
| 변경 TypeScript 파일 ESLint | 오류·경고 0건 |
| 전체 단위 테스트 | 최신 `dev`와 #161을 합친 격리 브랜치에서 134개 파일, 1,375개 통과 |

로컬 프로덕션 빌드는 검증 완료로 기록하지 않는다. 이 격리 작업 디렉터리는 저장소 밖의 `node_modules`를 링크해 사용해 Turbopack의 파일 범위 검사에 걸렸고, webpack 우회 빌드는 생성된 기존 라우트 타입 검사에서 실패했다. 해당 빌드는 새 서비스 코드의 통과 근거가 아니다. 최종 빌드 판정은 정상 의존성을 설치한 격리 CI 결과로 확인한다.

단위 테스트는 세 동작의 NULL 스냅샷 전달, 거절 뒤 두 시각의 원문 전달, 조회 후 고객 취소 요청이 끼어든 경우의 409, 스냅샷 인자 누락 시 DB 호출 전 거부, 기존 RPC 사용 동작을 확인한다.

## 실제 DB 통합 검증 게이트

`tests/integration/t54-atomic-transition.test.ts`는 격리 Supabase에서 NULL·비NULL 시각 비교, 행 잠금 경합, 고객 먼저/관리자 먼저, 이력·재고 불변, 권한 거부를 검사한다. `tests/integration/t35-cancel-request.test.ts`는 **서비스 → 저장소 → 0106 RPC** 경로에서 세 동작 모두 조회 후 고객 요청 시 409가 되는 경우와 관리자 전환 후 고객 요청이 0행 처리되는 경우를 추가로 검사한다.

이 브랜치의 실제 DB 통합 테스트는 아직 실행하지 못했다. 선행 PR의 최신 `dev` 병합 결과를 기준으로 격리 Supabase CI를 통과시키고, 리뷰어가 결과를 확인해야 한다. 운영 DB 적용·권한 확인은 DB1의 별도 승인 작업이며, 그 전에 새 RPC를 호출하는 앱을 배포하지 않는다. #160의 목록·실시간 버튼 연동은 별도 UI 작업이다.
