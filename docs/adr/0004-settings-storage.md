# ADR-0004: 설정값 저장 — 환경변수 vs 설정 테이블

> 상태: 승인 (2026-09-22, 사용자)
> 날짜: 2026-09-22
> 갱신: 2026-09-23 — T-34 송금 링크 실기기 검증 결과 반영

## 맥락

F-44(송금 정보 — 은행명·계좌번호·예금주·카카오페이 URL·토스 URL — 코드 하드코딩 금지, 값 변경 시 코드 수정 없이 반영, 비어 있으면 "준비 중" + 경고), F-17(만료 10분 — 설정값), F-24(자동 완료 ON/OFF·N분 — 관리자 설정 화면에서 변경), N-05(계좌번호·URL은 리포지토리 커밋 금지). 2차 F-36(임계값 N)도 설정값이다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 전부 배포 환경변수 | 저장소에 값이 남지 않고 읽기 구현이 단순함 | F-24는 관리자가 화면에서 바꾸는 값이므로 환경변수로는 불가(재배포 필요). 송금 정보 변경도 재배포가 필요하며 값을 배포 플랫폼에서 수정해야 함 |
| B. 전부 `app_settings` 테이블(key/value) | 관리자 화면에서 변경 즉시 반영, 재배포 없음, 값이 리포지토리에 없음(N-05 충족), 2차 설정 추가 시 행만 추가 | 테이블·API 필요. 값이 DB 백업에 남음(계좌번호는 고객 화면에 공개되는 값이라 시크릿이 아님 — N-05) |
| C. 혼합: 송금 정보=환경변수, 운영 설정=테이블 | — | 같은 성격의 운영값이 두 곳에 나뉘어 팀원이 저장 위치를 매번 판단해야 함 |

## 결정

**B.**

결정적 이유: F-24가 관리자 화면 변경을 요구하므로 테이블은 어차피 필요하고, 한 곳으로 통일하면 **"설정값은 `app_settings`"**라는 규칙 하나로 끝난다.

규격:

| key | 타입(문자열 저장) | 기본값(시드) | 공개 범위 |
|---|---|---|---|
| `payment.expire_minutes` | int | `10` | 관리자 |
| `auto_complete.enabled` | `true`/`false` | `false` | 관리자 |
| `auto_complete.minutes` | int | `15` | 관리자 |
| `transfer.bank_name` | text | `''` | 고객(공개) |
| `transfer.account_number` | text | `''` | 고객(공개) |
| `transfer.account_holder` | text | `''` | 고객(공개) |
| `transfer.kakaopay_url_template` | text — T-34 결과 금액 자리표시자 미사용 | `''` | 고객(공개) |
| `transfer.toss_url_template` | text — T-34 결과 현재 사용 중지 | `''` | 고객(공개) |

- 시드(`supabase/seed.sql`)에는 기본값·빈 문자열만 넣는다.
- 실제 계좌번호·송금 URL은 리포지토리에 커밋하지 않는다(N-05).
- 실제 값 입력은 다음 두 경로 중 하나를 사용한다.
  1. 관리자 대시보드 설정 패널(`PUT /api/admin/settings`)
  2. Supabase 대시보드 Table Editor
- 운영 입력 절차는 T-30 문서에서 정의한다.

## T-34 송금 링크 실기기 검증 결과

검증일: **2026-09-23**

### 카카오페이

- 실제 스마트폰에서 송금 링크 진입 확인.
- 송금 화면 진입은 가능.
- 주문 금액이 자동으로 입력되거나 고정되지 않음.
- 사용자가 송금 화면에서 **금액을 직접 입력해야 함**.
- 따라서 주문 합계를 URL 파라미터로 자동 입력·고정하는 방식은 사용하지 않는다.
- 실제 송금은 진행하지 않고 금액 입력 화면까지만 확인함.

**구현 결정**

T-31 고객 송금 안내 화면에서:

1. 주문 금액을 크게 표시한다.
2. 카카오페이 송금 링크 버튼을 제공한다.
3. "표시된 주문 금액과 동일한 금액을 직접 입력해주세요." 안내를 표시한다.

즉 카카오페이는 **직접 입력 폴백 방식**을 사용한다.

### 토스

- 실제 스마트폰 브라우저에서 `https://toss.me` 접속.
- **토스아이디 서비스 종료 안내**가 표시됨.
- 기존 `toss.me` 기반 개인 송금 링크는 현재 사용할 수 없음.
- 서비스 자체가 종료되어 금액 파라미터 자동 입력 여부를 검증할 수 없음.
- 실제 송금은 진행하지 않음.

**구현 결정**

- 기존 `toss.me` 송금 버튼은 고객 화면에 노출하지 않는다.
- `transfer.toss_url_template`은 공식 대체 방식이 확정되기 전까지 빈 문자열로 유지한다.
- 고객 API에서는 토스 설정을 `configured=false`로 처리한다.
- 향후 사용할 수 있는 공식 무료 송금 방식이 확인되면 별도 검토 후 다시 활성화한다.

## 금액 파라미터 정책

기존 설계에서는 송금 URL 템플릿에 `{amount}` 자리표시자를 넣어 주문 금액을 자동 입력하는 방식을 고려했다.

T-34 실기기 검증 결과:

- 카카오페이: 금액 자동 입력/고정 불가
- 토스: 기존 송금 링크 서비스 종료

따라서 **현재 사용하는 송금 수단에는 `{amount}`를 적용하지 않는다.**

향후 공식적으로 금액 파라미터를 지원하는 송금 수단이 추가되는 경우에만 `{amount}` 방식을 다시 사용한다.

## 고객 송금 설정 API

고객 API:

`GET /api/settings/transfer`

`transfer.*` 키만 화이트리스트 방식으로 노출한다.

선택한 송금 수단에 필요한 값이 비어 있으면:

- `configured=false`
- 서버 로그: `warn settings.transfer.missing`

으로 처리한다(F-44).

현재 기준:

- 은행 계좌이체: 설정값이 있으면 사용 가능
- 카카오페이: URL 설정 시 사용 가능, 금액 직접 입력 방식
- 토스: 대체 방식 확정 전까지 `configured=false`

## 저장 및 반영 방식

- 서버 읽기 캐시는 사용하지 않는다.
- 설정값은 요청마다 조회한다.
- 예상 주문 약 200건/일 규모이므로 별도 캐시 없이 운영한다.
- 관리자가 설정값을 수정하면 재배포 없이 즉시 고객 화면에 반영된다.

환경변수로 남는 것은 인프라 시크릿뿐이다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- (2차) `PHONE_ENCRYPTION_KEY`

새 환경변수 도입 시 `.env.example`에는 실제 값이 아닌 플레이스홀더만 추가한다.

## 결과 (트레이드오프 포함)

### 얻는 것

- F-44·F-24·F-17·(2차) F-36을 같은 테이블·같은 API에서 관리할 수 있다.
- 재배포 없이 축제 당일 계좌 또는 송금 설정을 변경할 수 있다.
- 실제 계좌번호·송금 URL이 Git 저장소에 남지 않는다.
- 실기기 검증 결과와 실제 구현 방식이 일치한다.

### 감수하는 것

- 카카오페이는 고객이 주문 금액을 직접 입력해야 하므로 오입력 가능성이 있다.
- 고객 화면에서 주문 금액을 크게 강조하고 직접 입력 안내를 명확히 표시한다.
- 토스 개인 송금 링크는 현재 사용할 수 없어 송금 수단 하나가 줄어든다.
- 설정 오타를 막기 위해 `PUT /api/admin/settings`에서 키별 zod 검증을 수행한다.
- Supabase Table Editor에서 직접 입력할 경우 애플리케이션 검증을 거치지 않으므로 T-30 운영 절차에 입력 형식 예시를 명시한다.
