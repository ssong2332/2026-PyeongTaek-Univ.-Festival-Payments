# 화면 디자인 변경 기록 (피그마 대비)

> 기준 디자인: 노션 원본 허브 "산출물"의 피그마 파일 "대동제 호떡"(Figma Sites, 모바일 393px 미리보기). 2026-10-01 화면별 캡처로 비교했다.
> 변경 권한: 팀장(박수홍) 2026-10-01 — "디자인은 판단해서 바꿔도 되고, 바꾼 내용은 기록한다"(DECISIONS #49). 시각 완성도는 디자인 재량이라는 원칙은 Architecture 8절(PRD #3)에 있다.
> 갱신 규칙: 피그마와 다르게 만들거나 피그마 요소를 빼면 이 문서에 한 줄 추가한다. 상태 열 값은 다음 중 하나다.
> - `작업 중`
> - `단위 테스트만`: 화면으로는 아직 확인하지 않았다.
> - `에이전트 화면 확인`: 구현 에이전트가 실제 브라우저에서 확인했다.
> - `확인됨(날짜)`: 375px 실제 화면을 캡처와 나란히 비교했다.
>
> 화면 확인은 로컬에 DB가 없어 브라우저에서 `/api/*` 응답만 DTO 모양의 가짜 값으로 바꿔서 했다. 앱 코드는 바꾸지 않았다. 대비 수치는 색 값으로 계산한 WCAG 대비비이고, 측정 도구로 잰 값이 아니다.

## 금지 — 피그마에 있어도 만들지 않는다

- 관리자 로그인 화면의 테스트 계정 목록과 역할 구분(총괄/주문/조리). 실제 로그인은 Supabase 이메일+비밀번호다(F-20). 피그마의 데모 계정 값은 코드·문서·PR 어디에도 옮기지 않는다.
- 고객 개인정보 입력(이름/별명, 요청사항). 주문 API `CreateOrderRequest`(strict)에 해당 필드가 없고, 개인정보 고지의 "수집 항목 없음"(F-12)과 충돌한다.
- 팀장이 확정하지 않은 운영 정책 문구(예: "거스름돈 반환 불가").

| 경우 | 처리 | 기록 위치 |
|---|---|---|
| spec·API에 있는 요소 | 피그마대로 만든다 | 기록 안 함 |
| 피그마에 있지만 spec·API에 데이터나 기능이 없다, 또는 장식 요소다 | 만들지 않는다. 팀장이 요청하면 추가 | 제외 표 |
| 위 "금지"에 해당한다 | 만들지 않는다 | 제외 표 |
| spec에는 있는데 피그마에 화면이 없다 (품절·로딩·오류·빈 값·취소/환불/만료) | 피그마의 색·모양 규칙으로 새로 만든다 | 변경 표 |
| 피그마대로 만들면 글씨 대비가 기준(보통 글씨 4.5:1, 큰 글씨 3:1)에 못 미친다 | 색이나 배치를 조정한다 | 변경 표 |
| 피그마 표현이 일부 상태에 맞지 않는다 | 조정한다 | 변경 표 |
| 표에 없는 경우 | 팀장에게 묻고 이 표에 행을 추가한다 | — |
