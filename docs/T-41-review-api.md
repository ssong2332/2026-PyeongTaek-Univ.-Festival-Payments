# T-41 후기 저장 API — DB1

F-37의 DB1 범위는 후기 스키마와 저장 API다. PR #102의 `0102_reviews.sql`에 이어
`POST /api/orders/{token}/reviews`를 추가한다. 고객 폼 연결은 FE1,
관리자 후기 목록·별점 평균은 T-42 담당 범위이며 이 PR의 완료 주장에 포함하지 않는다.

## 고객 폼 연결 계약

- 상태 페이지의 64자 소문자 16진수 토큰으로 호출한다. 별도 관리자 로그인은 필요 없다.
- 본문: `{ "rating": 4, "text": "맛있어요" }`. 별점은 정수 1~5, 텍스트는 선택이며
  생략·NULL·빈 문자열을 허용한다. 한글·이모지 모두 Unicode code point 200자까지다.
- 본문에 `orderId`·`statusToken` 등의 추가 필드는 받지 않는다.
- 성공: HTTP 201 `{ "createdAt": "2026-10-07T03:00:00.000Z" }`.
  폼은 성공 후 "후기가 등록되었습니다"와 함께 비활성화한다(FE1 연결).
- 400 `VALIDATION_ERROR`: 잘못된 JSON·입력. 입력을 고친 뒤 다시 제출할 수 있다.
- 404 `NOT_FOUND`: 토큰 형식 오류·주문 없음. 존재 여부를 구분하는 응답은 없다.
- 409 `REVIEW_NOT_ALLOWED`: 완료 상태가 아님. 상태를 다시 조회한다.
- 409 `REVIEW_ALREADY_SUBMITTED`: 이미 저장됨. 기존 후기를 덮어쓰지 않는다.
  성공 응답을 놓친 뒤 재시도한 경우도 같으므로 폼을 다시 제출하지 않게 처리한다.
- 500 `INTERNAL_ERROR`: DB 장애 등. DB 메시지·토큰·텍스트는 응답/로그에 넣지 않는다.
- 성공·오류 모두 `Cache-Control: private, no-store`. 고객용 후기 조회·수정·삭제는 추가하지 않는다.

## 저장 경계와 운영 적용

API → 서비스 → 저장소 순으로 검증한 토큰으로 주문을 조회하고 완료 상태를 검사한다.
저장소는 service_role로 INSERT만 수행한다. PK가 주문당 1건을 보장하고
완료 주문 검사 트리거의 행 잠금이 조회 이후 상태 변경 경합도 차단한다.
DB 트리거·FK 오류는 409/404로 변환하며 그 외 DB 오류는 고정 500이다.
후기 제출로 주문 상태·금액·재고를 수정하지 않는다.

새 마이그레이션은 없다. API 배포 전 기존 `0102_reviews.sql` 적용이 필요하며,
운영 DB 적용은 기존 배정 순서와 승인 절차를 따른다. 이 작업에서는 운영 DB를 변경하지 않았다.
