## 2분 중복 방지 원자성

기존 구현은 `최근 호출 조회 → 시간 비교 → INSERT` 순서여서 같은 주문에 동시 요청이 들어오면 두 요청이 모두 통과할 수 있었다.

현재 구현은 `create_staff_call_if_allowed(order_id, now)` PostgreSQL 함수에서 다음을 한 트랜잭션으로 처리한다.

1. 주문 ID 기준 transaction advisory lock 획득
2. 최근 호출 시각 확인
3. 120초 미만이면 새 행을 만들지 않고 남은 초 반환
4. 120초 이상이면 `staff_calls` 1행 생성

RPC는 `service_role`만 실행할 수 있고 `anon`, `authenticated`, `PUBLIC` 실행 권한은 제거한다.

## 자동 검증

### 단위·라우트·컴포넌트

- 고객 호출 성공 시 201
- 쿨다운 시 429 `CALL_COOLDOWN` + `Retry-After`
- 주문 토큰 없음/불일치 처리
- 관리자 호출 목록/확인 API 인증
- 고객 쿨다운 카운트다운
- 관리자 확인 처리 중 중복 클릭 차단
- 관리자 확인 실패 시 호출 유지 + 재시도 안내

### 실제 PostgreSQL 통합 테스트

`tests/integration/staffCallConcurrency.test.ts`

- 같은 주문·같은 시각의 호출 2건을 동시에 RPC 호출
- 성공 1건 / 거부 1건인지 확인
- DB의 `staff_calls`가 실제로 1행만 생성됐는지 확인
- 119초 재호출은 거부 + 남은 1초
- 정확히 120초 재호출은 허용

GitHub Actions의 local Supabase integration job에서 실행한다.
