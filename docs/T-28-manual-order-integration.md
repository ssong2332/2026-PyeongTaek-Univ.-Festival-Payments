# T-28 수기 주문 사후 입력 — 운영 연결

## 현재 구현

- 인증된 관리자 레이아웃 아래 `/admin/manual-orders`에서 종이 주문을 사후 입력한다.
- 메뉴·옵션·수량·결제수단·종이 주문 시각(KST)·종이의 M 번호를 입력하고 예상 금액 및 현재 재고 부족을 확인할 수 있다.
- M 번호는 화면에서 `M-` 접두사를 고정하고 숫자 1~9999를 직접 입력한다. DB에는 숫자로 저장하며 화면·CSV·관리자 주문표에서는 `M-001`처럼 표시한다.
- `POST /api/admin/manual-orders`와 `0104_manual_orders.sql`의 `create_manual_order`를 사용한다. 신규 저장은 201, 같은 멱등키 재요청은 200(`created=false`)이며 재고·매출을 중복 반영하지 않는다.
- 같은 M 번호는 DB UNIQUE/advisory lock으로 거부하며 API는 409 `MANUAL_NUMBER_TAKEN`을 반환한다. 화면은 공통 오류 envelope의 `error.code`를 읽어 입력값을 유지한 채 중복 안내를 표시한다.
- 메뉴는 `GET /api/admin/menus`로 읽는다. 비활성 메뉴와 과거 옵션도 종이 주문 사후 입력에 사용할 수 있도록 선택지에 남긴다. 0104 계약과 동일하게 비활성 옵션 그룹은 `minSelect`를 강제하지 않고 `maxSelect`는 유지한다.
- 재고가 부족해도 주문은 저장되고 재고는 0에서 멈춘다. 응답의 `stockShortages`를 화면에 표시한다.
- 저장 성공 후 새 idempotency key를 발급하고 입력 폼을 초기화한다. 네트워크/API 실패 시 입력값과 기존 idempotency key를 유지해 안전하게 재시도한다.
- 관리자 주문 목록·상세에서는 고객 `pickup_number` 대신 수기 주문의 `manual_number`를 `M-001` 형식으로 표시하고, 주문 시각은 `manual_ordered_at`을 사용한다.
- T-21 매출 통계, T-22 CSV, T-26 시간대별 히트맵은 수기 주문에 한해 `manual_ordered_at`을 날짜·시간 기준으로 사용한다.

## 운영 확인

`0104_manual_orders.sql`은 운영 적용 이력 확인 후 사용한다. 실제 운영 시작 전 관리자 로그인 환경에서 아래 스모크를 수행한다.

1. 현금 수기 주문 1건 저장 → M 번호, 주문 목록, 재고, 상태 이력, 통계, CSV 확인
2. 계좌이체 수기 주문 1건 저장 → 동일 항목 확인
3. 같은 M 번호를 다시 입력해 409 전용 중복 안내와 입력값 유지 확인
4. 같은 idempotency key 재요청이 기존 주문을 반환하고 재고·매출을 중복 반영하지 않는지 확인
