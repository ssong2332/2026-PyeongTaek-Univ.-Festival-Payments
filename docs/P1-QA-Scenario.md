# P1 프로토타입 QA 검수 시나리오

> 검수 예정일: 2026-09-28
> 검수 담당: 이주노(QA/팀장)
> 대상: P1 프로토타입 1
> 목표: **현금 주문 1건이 고객 메뉴 선택부터 관리자 처리 및 고객 상태 확인까지 정상적으로 완료되는지 검증**

## 1. P1 검수 범위

P1에서는 다음 흐름을 우선 검증한다.

`메뉴판 → 옵션/수량 선택 → 장바구니 → 현금 결제 선택 → 주문 생성 → 픽업 번호 발급 → 관리자 주문 확인 → 현금 수령 확인 → 조리중 → 완료 → 고객 상태 확인`

계좌이체 안내(T-31)는 P2 범위이므로 이번 P1 핵심 검수에서는 제외한다. 간편결제(카카오페이·토스)는 2026-09-24 제외 확정으로 검수 대상이 아니다.

---

## 2. 사전 조건

검수 시작 전 다음을 확인한다.

* Cloudflare Workers 배포 URL 접속 가능
* Supabase 연결 정상
* 테스트 메뉴 1개 이상 존재
* 테스트 메뉴 재고 2개 이상
* 관리자 계정 로그인 가능
* 고객 화면과 관리자 화면을 동시에 확인할 수 있는 기기 준비
* 가능하면 Android 또는 iOS 실기기 1대 + PC 관리자 화면 사용

---

## 3. 고객 메뉴판 검수

### QA-P1-01 메뉴판 접속

**절차**

1. QR 또는 배포 URL로 고객 메뉴판 접속
2. 메뉴 목록 확인

**기대 결과**

* 페이지가 정상적으로 열린다.
* 메뉴명과 가격이 표시된다.
* 판매 가능한 메뉴는 선택할 수 있다.
* 품절 메뉴가 있다면 품절 상태가 표시되고 선택할 수 없다.

---

### QA-P1-02 옵션 및 수량 선택

**절차**

1. 메뉴 선택
2. 옵션 선택
3. 수량을 1개 이상 선택
4. 장바구니에 추가

**기대 결과**

* 옵션 추가 금액이 정상 표시된다.
* 수량 변경이 가능하다.
* 재고보다 많은 수량을 선택할 수 없다.
* 장바구니 금액이 `메뉴 가격 + 옵션 추가 금액 × 수량`과 일치한다.

---

### QA-P1-03 장바구니

**절차**

1. 장바구니 이동
2. 수량 변경
3. 항목 삭제 후 다시 추가
4. 주문 진행

**기대 결과**

* 항목과 옵션이 그대로 유지된다.
* 수량 변경 시 총액이 즉시 변경된다.
* 항목 삭제가 정상 동작한다.
* 장바구니가 비어 있으면 주문 진행이 불가능하다.

---

## 4. 주문 생성 검수

### QA-P1-04 현금 결제 선택

**절차**

1. 결제 화면 진입
2. 아무 결제수단도 선택하지 않은 상태 확인
3. 현금 선택

**기대 결과**

* 결제수단 미선택 상태에서는 주문 확정이 불가능하다.
* 현금 선택 후 주문 확정이 가능하다.

---

### QA-P1-05 주문 생성

**절차**

1. 현금 선택
2. 주문 확정 버튼 1회 클릭

**기대 결과**

* 처리 중 버튼이 잠겨 중복 클릭되지 않는다.
* 주문이 한 건만 생성된다.
* 픽업 번호가 발급된다.
* 주문 상태 페이지로 이동한다.
* 최초 상태는 `결제대기`이다.
* 주문 금액이 장바구니에서 확인한 금액과 일치한다.

---

### QA-P1-06 재고 차감

**절차**

1. 주문 전 메뉴 재고 기록
2. 메뉴 1개 주문
3. 관리자 메뉴 또는 DB에서 재고 확인

**기대 결과**

* 주문 수량만큼 재고가 감소한다.
* 재고가 음수가 되지 않는다.

---

## 5. 관리자 검수

### QA-P1-07 관리자 로그인

**절차**

1. 비로그인 상태에서 `/admin` 접속
2. 관리자 계정으로 로그인

**기대 결과**

* 비로그인 사용자는 로그인 화면으로 이동한다.
* 정상 계정 로그인 후 관리자 대시보드로 이동한다.
* 앱 내 회원가입 기능은 존재하지 않는다.

---

### QA-P1-08 새 주문 확인

**절차**

1. 관리자 대시보드를 연 상태에서 고객 주문 생성
2. 새 주문 카드 확인

**기대 결과**

* 새로고침 없이 주문이 표시된다.
* 픽업 번호가 고객 화면과 동일하다.
* 결제수단이 `현금`으로 표시된다.
* 미확인 주문이 시각적으로 강조된다.

---

### QA-P1-09 주문 확인

**절차**

1. 새 주문의 확인 버튼 클릭

**기대 결과**

* 미확인 강조가 해제된다.
* 다른 주문의 상태는 변경되지 않는다.

---

### QA-P1-10 현금 수령 확인

**절차**

1. 테스트 고객에게 현금을 받았다고 가정
2. `[현금 수령 확인]` 클릭

**기대 결과**

* 주문 상태가 `결제대기 → 조리중`으로 변경된다.
* 현금 주문은 별도의 `결제확인` 단계를 거치지 않는다.
* 같은 버튼을 반복해서 눌러 잘못된 상태 변경이 발생하지 않는다.

---

### QA-P1-11 완료 처리

**절차**

1. 조리중 주문의 `[완료]` 버튼 클릭

**기대 결과**

* 주문 상태가 `완료`로 변경된다.
* 완료된 주문에 허용되지 않는 상태 변경 버튼이 활성화되지 않는다.

---

## 6. 고객 상태 페이지 검수

### QA-P1-12 관리자 상태 변경 반영

**절차**

1. 고객의 주문 상태 페이지를 계속 열어둔다.
2. 관리자가 현금 수령 확인
3. 관리자가 완료 처리

**기대 결과**

* 고객 화면이 `결제대기 → 조리중 → 완료` 순서로 갱신된다.
* 고객이 페이지를 새로 열어도 같은 주문을 확인할 수 있다.
* 픽업 번호가 변경되지 않는다.

---

### QA-P1-13 잘못된 주문 URL

**절차**

1. 존재하지 않는 상태 토큰으로 접근

**기대 결과**

* 다른 고객의 주문 정보가 노출되지 않는다.
* `주문을 찾을 수 없음` 또는 이에 해당하는 화면이 표시된다.

---

## 7. 예외 검수

### QA-P1-14 재고 부족

재고보다 많은 주문을 시도한다.

**기대 결과**

* 주문이 생성되지 않는다.
* 재고가 잘못 차감되지 않는다.
* 고객에게 재고 부족 안내가 표시된다.

### QA-P1-15 중복 주문 방지

주문 확정 버튼을 빠르게 여러 번 누르거나 동일 요청을 재시도한다.

**기대 결과**

* 실제 주문은 한 건만 생성된다.
* 재고도 한 번만 차감된다.
* 픽업 번호가 중복 발급되지 않는다.

### QA-P1-16 새로고침

주문 완료 후 상태 페이지를 새로고침한다.

**기대 결과**

* 주문이 새로 생성되지 않는다.
* 기존 픽업 번호와 상태가 그대로 표시된다.

---

## 8. P1 완료 판정

다음 조건을 모두 만족하면 P1 QA 통과로 판단한다.

* 고객이 메뉴를 정상적으로 선택할 수 있음
* 옵션·수량·총액 계산 정상
* 현금 주문 생성 정상
* 주문 중복 생성 없음
* 재고 차감 정상
* 픽업 번호 정상 발급
* 관리자 대시보드에 주문 표시
* 현금 수령 확인 시 조리중 전환
* 완료 처리 정상
* 고객 상태 화면에 관리자 변경사항 반영
* 다른 주문 정보 노출 없음
* 치명적인 UI 오류 없음
* 빌드 및 관련 테스트 통과 근거 확인

검수 중 발견한 문제는 다음 형식으로 기록한다.

`[P1-버그번호] 화면 / 재현 절차 / 실제 결과 / 기대 결과 / 심각도 / 담당자`

심각도:

* **Blocker**: 주문 흐름 진행 불가능
* **High**: 결제·재고·상태·주문 데이터 오류
* **Medium**: 기능은 가능하지만 운영에 불편
* **Low**: 문구·정렬·경미한 UI 문제
