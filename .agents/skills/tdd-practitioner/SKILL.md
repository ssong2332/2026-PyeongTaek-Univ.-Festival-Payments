# TDD Practitioner

이 스킬은 새 기능 구현이나 버그 수정 시 **테스트 우선(Test-First)** 방식을 체계적으로 실행하도록 안내합니다.

## 핵심 원칙
1. **No Code Without Test**: 테스트 없는 기능 구현은 미완료 상태다.
2. **Red-First**: 반드시 실패하는 테스트를 먼저 작성하고 실행하여 실패를 직접 확인한다.
3. **Minimal Green**: 테스트를 통과시키는 가장 단순하고 명확한 최소한의 코드만 작성한다.
4. **Refactor with Confidence**: 테스트가 통과하는 상태를 유지하며 구조와 가독성을 개선한다.

## 1. 새 기능 개발 절차 (Feature Workflow)
1. **요구사항 분석 및 테스트 케이스 목록화**
   - Given-When-Then 형식으로 시나리오 정의
   - 정상 케이스(Happy Path) 1개 + 경계값(Boundary) 2개 이상 + 예외 케이스(Error) 2개 이상 도출
2. **실패하는 단위/통합 테스트 작성 (Red)**
   - 기대하는 인터페이스(함수 시그니처, 파라미터, 반환값)를 테스트 코드에서 먼저 정의
   - 테스트 실행 → 실패(Expected Failure) 출력 확인
3. **최소 구현 작성 (Green)**
   - 테스트를 통과시키는 최소 로직 작성
   - 테스트 실행 → 전원 통과(All Passed) 확인
4. **리팩토링 (Refactor)**
   - 중복 제거, 네이밍 개선, 함수 분리
   - 테스트 재실행으로 회귀(Regression) 없음 검증

## 2. 버그 수정 절차 (Bugfix Workflow)
1. **재현 테스트 작성 (Reproduce)**
   - 보고된 결함 상황을 정확히 재현하는 실패 테스트를 작성
   - 테스트 실행 → 버그 발생으로 인한 실패 확인 (이 과정 없이 코드 수정 착수 금지)
2. **원인 코드 수정 (Fix)**
   - 버그의 근본 원인을 수정
3. **검증 (Verify)**
   - 재현 테스트 통과 확인 + 기존 전체 테스트 스위트 회귀 검증

## 3. 부실 테스트(Flaky/Shallow Test) 방지 체크리스트
- [ ] 입력값에 `null`, `undefined`, 빈 문자열, 0, 음수, 최대/최소값이 포함되어 있는가?
- [ ] 단순 타입 검사나 껍데기 실행(호출 여부만 검사)이 아닌 실제 반환값과 상태 변화를 단언(Assert)하고 있는가?
- [ ] 비동기 작업(Async)의 경우 완료 대기(await/Promise)가 확실하게 처리되어 비결정적(Flaky) 실패가 없는가?
- [ ] 외부 의존성(네트워크, DB, 파일 I/O)이 격리된 Mock/Stub으로 적절히 통제되었는가?
